# Дольки

**Дольки** — концепция сервиса для коллективных сборов на подарок, где каждый участник вносит равную долю, а сумма сбора прозрачна и подтверждена чеком.

Учебный пет-проект по бизнес-анализу.

## Какую проблему решает

| Проблема | Как решают «Дольки» |
| --- | --- |
| Непрозрачная сумма: неясно, из чего она складывается и сколько стоил подарок | Каждая позиция добавляется со ссылкой на товар или услугу, сумма сбора равна сумме позиций, после покупки организатор прикладывает чек |
| Неравный вклад: одни переводят больше, другие меньше | Сумма делится поровну, взнос сверх дольки возможен только с разрешения организатора |
| Нагрузка на организатора: напоминания, учёт вручную, доплаты из своих | Сервис сам считает дольки и показывает прогресс сбора, взносы копятся на отдельном накопительном счёте |

## Что внутри

```
dolki/
├── index.html                ← лендинг: описание сервиса
├── app.html                  ← веб-приложение: создание сбора, регистрация, приглашения, профиль
├── config.js                 ← ключи подключения к Supabase (общие для всех страниц)
├── supabase/
│   ├── schema.sql            ← вся база с нуля: таблицы, правила доступа, функции, хранилище чеков
│   └── receipts.sql          ← только чеки — для базы, где schema.sql уже запущен
├── fonts/
│   └── Chicoree-OFL.txt      ← лицензия шрифта Chicoree
└── README.md
```

Сайт сделан на чистых **HTML, CSS и JavaScript**: без фреймворков, сборщиков, серверов и Docker. Стили и скрипты лежат внутри самих HTML-файлов, шрифт заголовков встроен в них же. Отдельно вынесен только `config.js` с настройками базы данных.

## Как открыть сайт на своём компьютере

1. Скачайте репозиторий: зелёная кнопка **Code** → **Download ZIP**.
2. **Обязательно распакуйте архив**: правой кнопкой по архиву → «Извлечь все…» (на macOS — двойной клик).
3. Откройте распакованную папку и запустите **`index.html`** двойным кликом. Он откроется в браузере.
4. Кнопка **«Создать сбор»** откроет `app.html` в новой вкладке.

### Если «Создать сбор» не открывается

Лендинг ищет файл `app.html` **в той же папке**, где лежит сам. Поэтому:

- **Не открывайте `index.html` прямо из ZIP-архива** без распаковки: тогда браузер видит только один файл, и второй ему недоступен.
- **Не переименовывайте файлы.** Если при скачивании браузер назвал файл `app (1).html`, переименуйте его обратно в `app.html`.
- `index.html`, `app.html` и `config.js` должны лежать **рядом, в одной папке**.

> Для заголовков интернет не нужен: шрифт встроен в файлы. Без интернета основной текст покажется системным шрифтом вместо Manrope, на работу сайта это не влияет.

## Как опубликовать сайт через GitHub Pages

1. Загрузите файлы в репозиторий так, чтобы `index.html` и `app.html` лежали **в корне** репозитория.
2. Откройте **Settings** → **Pages**.
3. В блоке **Build and deployment** выберите **Source: Deploy from a branch**, ветку **main** и папку **/ (root)**, нажмите **Save**.
4. Через минуту-две сайт появится по адресу `https://<ваш-логин>.github.io/<название-репозитория>/`.

## Подключение базы данных (Supabase)

Без настройки приложение работает в **демо-режиме**: всё можно пройти, но ничего не сохраняется. Чтобы появились настоящие аккаунты и сохранялись сборы, подключите бесплатную базу Supabase (PostgreSQL).

### 1. Создайте проект
1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и нажмите **New project**.
2. Придумайте название и пароль базы, выберите регион, дождитесь запуска (1–2 минуты).

### 2. Создайте таблицы и функции
1. Откройте **SQL Editor** → **New query**.
2. Скопируйте туда весь файл [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**.

> ⚠️ Скрипт пересоздаёт таблицы: если в базе уже были данные, они удалятся.
>
> Если `schema.sql` предыдущей версии (без чеков) у вас уже запущен и данные жалко, запустите вместо него только [`supabase/receipts.sql`](supabase/receipts.sql): он добавит чеки, ничего не удаляя.

Скрипт также создаёт в **Storage** закрытое хранилище `receipts` для файлов чеков (фото или PDF, до 5 МБ).

### 3. Включите анонимные сессии
**Authentication** → **Sign In / Providers** → включите **Allow anonymous sign-ins**.

Это технический шаг: каждый браузер получает служебную сессию Supabase, а аккаунт пользователя (телефон и пароль) привязывается к ней при входе. Подробнее — в разделе «Как устроены аккаунты».

### 4. Вставьте ключи в `config.js`
1. Откройте **Project Settings** → **API Keys** и скопируйте **Project URL** и **publishable key** (или **anon public key**).
2. Откройте `config.js` в любом текстовом редакторе и вставьте значения:

```js
window.DOLKI_CONFIG = {
  SUPABASE_URL: 'https://ваш-проект.supabase.co',
  SUPABASE_KEY: 'sb_publishable_...'
};
```

Файл подключают обе страницы: так лендинг тоже узнаёт, вошли вы или нет, и показывает в шапке «Войти» или «Мои сборы» и кнопку профиля.

> Этот ключ публичный: он предназначен для браузера и спокойно лежит в открытом коде. Данные защищают не он, а правила доступа в базе. **Никогда не вставляйте в сайт `service_role` или secret key**: эти ключи обходят все правила доступа.

### 5. Проверьте
1. Нажмите **«Войти»** → вкладка **«Регистрация»** и зарегистрируйтесь.
2. В Supabase откройте **Table Editor** → `accounts`: там появится ваш аккаунт, а в колонке `password_hash` вместо пароля будет хэш вида `$2a$10$…`.
3. Выйдите из аккаунта (Профиль → «Выйти из аккаунта») и войдите снова по номеру и паролю, можно в другом браузере. Ваши сборы на месте.

## Как устроены аккаунты

Вход по номеру телефона через стандартную авторизацию Supabase требует платного SMS-провайдера. Поэтому аккаунты сделаны в собственной таблице базы, а проверка паролей работает на сервере:

1. **Регистрация.** Сервер (функция `register_account`) проверяет данные и сохраняет пароль только в виде **хэша bcrypt**: `crypt(пароль, gen_salt('bf', 10))` из расширения pgcrypto. Соль уникальна для каждого пароля и хранится внутри хэша. Сам пароль в базу не попадает.
2. **Вход.** Функция `login_account` хэширует введённый пароль с той же солью и сравнивает результат с сохранённым хэшем. При совпадении браузер привязывается к аккаунту (таблица `account_sessions`).
3. **Выход.** Функция `logout_account` удаляет привязку браузера к аккаунту. Войти снова можно с любого устройства.

Защита:
- **Хэши не видны никому:** к таблицам `accounts` и `account_sessions` из браузера нет прямого доступа (RLS включён, политик нет). Наружу отдаются только имя и телефон текущего пользователя (функция `me`).
- **От перебора паролей:** после 5 неверных попыток подряд вход блокируется на 15 минут.
- **От выяснения, зарегистрирован ли номер:** для несуществующего номера и для неверного пароля ответ одинаковый — «Неверный номер телефона или пароль».
- **Минимальная длина пароля** — 8 символов, проверяется и в браузере, и на сервере.

### Как устроено хранение

| Что | Где хранится |
| --- | --- |
| Аккаунт: телефон, имя, хэш пароля, счётчик неудачных входов | `accounts` |
| Какой браузер в какой аккаунт вошёл | `account_sessions` |
| Сбор: повод, получатель, дата, число участников, код приглашения | `collections` |
| Позиции: ссылка, название, цена | `items`; сумма сбора не хранится, а считается как сумма цен позиций |
| Участники и их взносы | `memberships` |
| Чек: путь к файлу, тип, сумма по чеку, дата | `receipts` |
| Файлы чеков | Supabase Storage, закрытый бакет `receipts`, папка = id сбора |

### Серверные функции

| Функция | Что делает |
| --- | --- |
| `register_account`, `login_account`, `logout_account` | Регистрация, вход и выход |
| `me`, `update_profile`, `change_password` | Данные текущего пользователя, изменение имени и телефона, смена пароля |
| `get_invite(code)` | Показывает сбор по коду приглашения: позиции, дольку, прогресс. Без телефонов и id пользователей |
| `join_collection(code)` | Добавляет пользователя в сбор, если сбор открыт, срок не прошёл и есть свободные места |
| `demo_pay(cid, amount)` | Имитирует оплату дольки: не меньше дольки, больше — только если организатор разрешил |
| `get_members(cid)` | Список участников с именами и статусом оплаты, только для участников сбора |
| `attach_receipt(cid, path, type, total)` | Прикрепляет чек: только организатор, только когда собрана вся сумма. Сбор получает статус «подарок куплен» и закрывается для взносов |
| `get_collection_state(cid)` | Статус сбора, собранная сумма и чек — для страницы организатора |

Права доступа к сборам задаются правилами **Row Level Security**: каждый пользователь видит только свои сборы и сборы, в которых участвует; менять позиции может только организатор. Те же правила действуют для файлов чеков в хранилище: загрузить чек в папку сбора может только его организатор, открыть — только организатор и участники. Файлы открываются по временной ссылке, действующей 1 час.

### Ограничения
- Код из СМС при регистрации имитируется: подходят любые 4 цифры, настоящие СМС не отправляются.
- Восстановления пароля нет: для него нужна настоящая отправка СМС.
- Supabase советует включить CAPTCHA для анонимных сессий, чтобы защититься от ботов: **Authentication** → **Attack Protection**.
- Данные граждан РФ по 152-ФЗ должны храниться на серверах в России. Для учебного проекта с тестовыми данными это не критично, для реального сервиса нужен российский хостинг.

## Что можно попробовать

**На лендинге (`index.html`):**
- кнопка «Оплатить мою дольку» в карточке-примере закрашивает дольки грейпфрута и пересчитывает собранную сумму;
- позиции «На что собираем» раскрываются по клику;
- меню плавно прокручивает к разделам, на телефоне сворачивается в «бургер».

**В приложении (`app.html`):**
1. **Сбор:** повод, получатель, дата, позиции со ссылками и ценами. Грейпфрут в предпросмотре делится на столько долек, сколько участников.
2. **Регистрация и вход:** по кнопке «Войти» в шапке или в процессе создания сбора. Регистрация — имя, российский номер (10 цифр), пароль и код из СМС (в демо подходят любые 4 цифры). Вход — номер и пароль.
3. **Приглашение:** страница созданного сбора со ссылкой для участников и списком участников.
4. **Мои сборы** (при подключённой базе): список ваших сборов с прогрессом, кнопка появляется в шапке после регистрации.
5. **Профиль** (при подключённой базе): кнопка с вашим именем в шапке обеих страниц. В профиле видно, сколько сборов вы организовали и в скольких участвуете; там же можно изменить имя и телефон, сменить пароль и выйти из аккаунта.
6. **Покупка и чек** (при подключённой базе): когда собрана вся сумма, у организатора на странице сбора появляется кнопка «Купить и приложить чек». Он загружает фото или PDF чека и указывает сумму, после чего сбор закрывается. Участники видят чек на странице сбора.
7. **Страница приглашённого** (при подключённой базе): откройте ссылку-приглашение в другом браузере или в режиме инкогнито. Видно, на что собирают и какая долька; можно присоединиться, зарегистрироваться и оплатить дольку. Организатор видит на своей странице, кто вступил и кто оплатил.

## Ограничения демо-версии

- Без подключения Supabase данные не сохраняются: после перезагрузки страницы сбор пропадает.
- Оплата имитируется функцией `demo_pay`: деньги не списываются. В настоящем сервисе взнос отмечал бы сервер после подтверждения оплаты банком.
- Чек проверяется только по формату и размеру файла; сверки с ФНС по QR-коду нет.
- Карточки товаров по ссылке не подтягиваются автоматически: название и цену нужно ввести вручную.
- Ссылка-приглашение (`dolki.example/...`) демонстрационная и никуда не ведёт.
- Регистрация и СМС-код имитируются, настоящий код не отправляется.
